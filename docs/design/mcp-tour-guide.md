# MCP サーバーとツアーガイド

作成日時: 2026-11-06 20:04
更新日時: 2026-11-09 22:12

Claude Code や Codex、ローカル LLM(Gemma 4 26B を想定)から、アプリのカメラを動かせるようにする計画と、その実装のメモ。「ドナウ川を見せて」「世界の長い川を順に見せて」と頼むと、LLM が行き先と説明を決め、アプリがそこへ飛んで見せる。2026-11-06 に MCP サーバーの最初の版を作った(下の「実装(2026-11-06)」)。

## 実装(2026-11-06)

- **置き場所:** `src/main/mcp-server.ts`(メインプロセス)。公式の SDK(`@modelcontextprotocol/sdk` 1.32.2、`zod` 4.6.7)の Streamable HTTP を状態を持たない使い方で使い、要求ごとにサーバーを作る。`http://127.0.0.1:47815/mcp` で待ち受け、POST だけを受ける。
- **オンオフ:** 設定の「パフォーマンス」の「外部との連携」の「MCP サーバー」(既定はオフ)。起動時と設定を変えたときに、メインプロセスが設定を見て待ち受けを始める・止める。アプリを終えるときは止める。
- **画面との受け渡し:** ツールの処理は画面で行う。メインプロセスが `mcp:call` で頼み、画面(`src/renderer/mcp-bridge.ts`)が `mcp:reply` で結果を返す(30 秒で打ち切り)。画面側の操作は `globe-view.ts` の `remote` にまとめた。`screenshot` だけはメインプロセスで画面を撮る(幅 1280 の JPEG)。2026-11-09 に録画の `start_recording`、`stop_recording`(画面で録る)と `set_video_size`(メインプロセスでウィンドウの大きさを変える)を足した(plan.md の「録画」)。
- **ツール(14):** `get_view`(視点、モード、中心、高さ km、時刻、中心での太陽の高さ、ツアーの進み具合)、`fly_to`(緯度、経度、高さ km、方角、傾き、旋回)、`highlight`(river / area / point / line / arrow / polygon と見た目の指定。結果に名前、範囲、通る国)、`frame_highlights`、`clear_highlights`、`show_caption`、`clear_caption`、`play_tour`、`stop_tour`、`set_time`(地方時か日時、省くと今)、`set_mode`、`set_view`、`set_map_lines`(この場だけ。設定は変えない)、`screenshot`。引数は JSON Schema(zod)で形を決め、外れた値や見つからない名前は理由を付けて `isError` で返す。
- **地球ビューから:** `highlight` のあとの `frame_highlights` と `fly_to` は、地球ビューからでも地域ビューに入ってカメラを寄せる。風速モードと太陽系の視点では断る。
- **Claude Code への登録:** `claude mcp add --transport http weather-globe http://127.0.0.1:47815/mcp`(アプリを起動し、設定で MCP サーバーをオンにしておく)。
- **確かめたこと:** 実アプリ(データのコピー、設定でオン)に JSON-RPC を直接送り、`initialize`、`tools/list`(14 個)、`get_view`、`set_mode`、`highlight`(アルプス山脈、モンブラン、存在しない川でエラー)、`frame_highlights`(地球ビューから地域ビューへ入ってアルプスに寄る)、`show_caption`、`set_time`(地方時、日時の誤りでエラー、今に戻す)、`screenshot`(約 200KB の JPEG で、アルプスと字幕が写る)、`fly_to`(富士山へ高さ約 420km)、`play_tour`(ヒマラヤの 6 場面)、`stop_tour` が動くことを確かめた。Claude Code に登録して自然な言葉で頼む確認はまだしていない。
- **ツアーの保存(2026-11-07):** 右上の「ツアー」パネル(`tour-panel.ts`)。保存していないツアーを再生している間は、名前の欄と「保存」のボタンを出す。名前の既定は `play_tour` の `title`、なければ最初の場面の字幕の最初の文(30 文字まで)、それもなければ日時(`tour-library.ts`)。保存したツアーは一覧に並び、名前を押すと再生、再生中のものは停止の印になる。ゴミ箱のボタンは誤って消さないよう、1 回押すと色が変わり、3 秒以内にもう 1 回押すと消える。保存先は `data/tours.json`(台本は大きくなるので `settings.json` とは別)で、バックエンドの `GET /tours`、`PUT /tours/{id}`、`DELETE /tours/{id}` が読み書きする。台本の中身(場面の形)はバックエンドでは確かめず、MCP の zod の形に任せる。`play_tour` に `title`(パネルに出る名前)と `save`(始めると同時に保存する)を足した。太陽系とデモの間はパネルを隠す。設定の「表示」の「ツアーのパネルを表示」で隠せる。名前の変更と並べ替えはまだない。
- **まだないこと:** ツアーを秒数で自動で進める指定、合言葉(トークン)、ポートの設定、stdio しか使えないクライアント向けの中継。

## 方針

- **アプリに LLM を持たない:** アプリは「カメラを動かすツール」を MCP サーバーとして公開するだけにする。考える役は外の LLM(MCP クライアント)が受け持つ。goals.md の「LLM はローカルで、必要なときだけ読み込み、VRAM を占有し続けない」と矛盾しない。アプリは LLM を起動も常駐もさせない。
- **どの LLM からでも使える:** MCP に対応したクライアントなら同じツールを呼べる。Claude Code、Codex、ローカル LLM を動かす MCP 対応のアプリ(LM Studio など)を、アプリを変えずに切り替えて比べられる。
- **地名検索は要らない:** 「ドナウ川」の緯度・経度や範囲は LLM が知っている。アプリは座標と範囲を受け取るだけにする。
- **長い手順を LLM に回させない:** ツアーは台本(行き先の一覧)を 1 回で受け取り、アプリが自分で進める(`play_tour`)。小さめのモデルが一番苦手なのは、ツールを何度も順に呼び続けることなので、そこをアプリが受け持つ。

## 構成

```
Claude Code / Codex / LM Studio(Gemma 4 26B など)
   │  MCP(Streamable HTTP、http://127.0.0.1:<ポート>/mcp)
   ▼
Electron メインプロセス … MCP サーバー(@modelcontextprotocol/sdk)
   │  IPC
   ▼
画面(globe-view.ts) … 既存のカメラの移動、モードと視点の切り替え、字幕
```

- **置き場所:** MCP サーバーはメインプロセスに置き、アプリが起動している間だけ受け付ける。
- **接続先:** `127.0.0.1` だけで待ち受け、外からはつながらない。
- **ポート:** 固定(例: 47815)にし、設定で変えられるようにする。
- **Claude Code の登録:** `claude mcp add --transport http weather-globe http://127.0.0.1:47815/mcp`
- **Codex と LM Studio:** HTTP の MCP サーバーに対応していれば、同じ URL を登録する。stdio しか使えないクライアントのために、標準入出力を HTTP へ中継するだけの小さなスクリプト(`scripts/mcp-stdio.mjs`)を用意する。設定の書き方は作るときに確かめる。
- **オンオフ:** 設定の「パフォーマンス」か新しいタブで、MCP サーバーを使うかを選べるようにする(既定はオフ)。

## ツール

| ツール | 引数 | 動き |
|---|---|---|
| `fly_to` | 緯度、経度、高度 km(または範囲 km)、方位、傾き | そこへ飛ぶ。高度で地球ビューと地域ビューを自動的に選ぶ。着いてから結果を返す |
| `show_area` | 南端、北端、西端、東端(度) | 範囲全体が画面に収まる高さと向きで映す(「ドナウ川全体」など) |
| `set_mode` | `normal` / `weather` / `wind` | 表示モードを切り替える |
| `set_view` | `globe` / `region` / `solar` | 視点を切り替える |
| `set_time` | 時刻(過去 24 時間以内) | 時刻のスライダーを動かす |
| `set_map_lines` | 海岸線と国境線を出すか | 設定の「海岸線と国境線を表示」と同じ。ハイライトを見やすくしたいときなどに切り替える。切り替えはふわっと変わる |
| `highlight` / `clear_highlights` | 対象(下の「ハイライト」) | 川をなぞる、範囲を示す、山頂などに印を立てる。消す |
| `show_caption` / `clear_caption` | 文、秒数(省くと消すまで) | 画面の下の中央に説明の字幕を出す。端末に出る LLM の答えとは別に、アプリの画面で説明できる |
| `get_view` | なし | 今のカメラの位置、高度、モード、視点、時刻、昼夜(太陽の高度)を返す |
| `screenshot` | なし | 今の画面を画像で返す。LLM が「狙いどおりに映ったか」を見て直せる |
| `play_tour` | 行き先の一覧(下) | ツアーを始める。アプリが順に進める |
| `stop_tour` | なし | ツアーを止め、元の視点に戻す |

- **既存の処理を使う:** カメラの移動は、視点の保存の呼び出し(遠くへは弧を描いて飛ぶ)と同じ処理を使う。
- **人の操作が優先:** 人が地球をドラッグしたりキーを押したりしたら、ツアーと飛行は止める(デモと同じ)。

### `play_tour` の台本

```json
{
  "title": "世界の長い川",
  "stops": [
    {
      "name": "ナイル川",
      "area": { "south": -3, "north": 31.5, "west": 24, "east": 40 },
      "caption": "全長約 6,650km。ビクトリア湖から地中海へ、11 か国を流れます。",
      "seconds": 15,
      "mode": "normal"
    },
    {
      "name": "アマゾン川",
      "center": { "lat": -3.5, "lon": -60 },
      "range_km": 3000,
      "caption": "流域面積は世界最大。河口の幅は 300km を超えます。",
      "seconds": 15
    }
  ]
}
```

- **行き先:** `area`(範囲)か、`center` と `range_km`(中心と映す広さ)のどちらかで指定する。
- **見せ方:** 飛ぶ、着いたら字幕を出す、`seconds` だけ見せる、次へ進む、をアプリが回す。デモの進行(`demo-controller.ts`)を土台にする。
- **字幕:** 画面の下の中央に名前と説明を出す。文が長すぎるときは折り返し、上限の文字数を決めておく。
- **途中の様子:** ツアーの進み具合は `get_view` で返し、LLM が途中で確かめられるようにする。
- **受け付ける形:** 台本は JSON Schema で形を決め、外れた値(緯度が範囲外、`seconds` が極端など)は理由を付けて断る。小さめのモデルの書き間違いを、その場で直させるため。

## ハイライト(川をなぞる、範囲を示す)

2026-11-06 に描画の部分だけ試作した(ブランチ `feature/map-highlights`)。まだ MCP にはつないでおらず、検証用フック(`window.__weatherGlobeDebug.highlight(spec)`、`clearHighlights()`)から呼ぶ。

- **データ:** Natural Earth の `ne_10m_rivers_lake_centerlines`(川)と `ne_10m_geography_regions_polys`(山脈、砂漠、高原、半島、島など)を、`scripts/build-highlights.mjs` で `src/renderer/data/rivers-10m.json`(1,065 件、1.9MB)と `regions-10m.json`(1,046 件、2.2MB)に変換した。点を約 400m の許容で間引き、小数を 3 桁に丸める。初めて使うときだけ読み込む(Vite で別のファイルに分かれる)。
- **名前:** 川は英語名(`name_en`)でまとめ、現地の名前を別名に持つ(ドナウ川は Danube と Donau に分かれていた)。日本語名はない。範囲は英語名と日本語名(`NAME_JA`、全件にある)で引ける。大文字小文字、アクセント記号、「〜川」「~ River」などの付け足しは無視する(`highlight-data.ts` の `findByName`)。候補が複数あるときは大きなもの(scalerank の小さいもの)を選ぶ。
- **川の向き:** Natural Earth の川は線の向きがまちまちなので、変換のときに源流から河口へそろえ、各線に源流からの距離を付ける。端点(約 3km 以内は同じ点とみなす)でつないだ網の中で最も離れた 2 点を本流の両端とし、片方だけが海岸(同梱の 50m の海岸線)に近ければそちらを河口、どちらとも言えなければ本流の線の多くの向きに合わせる。ドナウ、ナイル、アマゾン、長江、ミシシッピ、ヴォルガ、メコン、ガンジス、ニジェールなどで、源流と河口が正しいことを確かめた。
- **描き方(`highlights.ts`):** 川は画面上で幅 5 画素の光る帯で、4 秒かけて源流から河口へ伸び、伸びている先端を明るくする。範囲は半透明の塗り(地表に沿うよう三角形を 0.6 度以下に分ける)と、1.6 秒かけて描かれる縁取り。次のものを示すと、前のものは 0.7 秒でふわっと消える。座標を直接渡す線(`line`)と多角形(`polygon`)も描ける。太陽系の視点では隠す。
- **太さのある矢印(`arrow`、2026-11-07):** 進軍や移動の大きな流れを示す、地表に貼り付いた帯の矢印(`thick-arrow.ts`、単体テストあり)。`points`([緯度, 経度] の並び、根元から先端へ)と `width`(太さ km。省くと長さの 3.5%、10〜150km)。渡した点を直線で結び、角だけを丸めてから帯にする(角の手前と先、帯の太さの 2 倍の所を、角を制御点にした 2 次ベジェ曲線でつなぐ。前後の線分が短いときはその半分まで)。曲がる所には点を置く。はじめは点を必ず通るなめらかな曲線(セントリペタル Catmull-Rom)にしていたが、アレキサンダーの行って戻る道で折り返しの外へ輪のようにはみ出し、点の間隔がばらばらな所でうねったのでやめた。135° より大きく曲がる所(来た道を戻る所)では、無理に曲げずに矢印を分け、そこに矢じりを付ける(`splitAtSharpTurns`、`buildSplitArrow`)。2 本目からは根元を帯の太さの 0.8 倍だけ先から始め、前の矢じりと重ねない。進み具合は全体を通した値にして、1 本目が伸びきってから 2 本目が伸びる。分けた本数に合わせて伸びる時間を延ばす(1 本増えるごとに 25%、最大 2 倍)。`fade` は最初の 1 本の根元だけに効く。ラベルは 1 つ。はじめは 110° にしていたが、ただの曲がり角(112〜113°)でも切れ、アレキサンダーの場面 1 が 8 本に分かれたので上げた。今は場面 1 がシーワ・オアシス、ペルセポリス、アレクサンドリア・エスカテ、ヒュファシス川の 4 か所で分かれる。太さは地表の距離なので、寄れば太く、引けば細く見える。帯は根元から先まで同じ太さで(はじめは根元を先の 55% にして先へ太らせていたが、道筋が読みにくいので一定にした)、先端に帯の 1.9 倍の幅の矢じり(長さは幅の 1.3 倍、全体の 40% まで)。はじめは長さの 6%(最大 300km)、矢じりは幅 2.1 倍・長さ 1.6 倍にしたが、大きすぎて急な曲がり角で帯が重なったので細くした。今の太さ(1,000km の行軍で約 35km、短い移動は 10〜12km を指定)が、ユーザーと確かめた見た目の基準。太くするときは、このバランスを崩さないようにする。塗り(中央 0.6、縁で 0.75)と、線と同じ光る縁取りで、3 秒かけて根元から先へ伸び、伸び終えると流れる光が通る。`dashed` では塗りも縁取りも同じ区切りの破線にする(塗りと隙間の 1 組を帯の太さの 3 倍、塗り 60%。矢じりと矢じりの縁は区切らない。`arrowDashCount`)。区切りは矢じりの根元から逆算して、矢じりのすぐ手前を必ず塗る(矢じりに尾が付く。頂点ごとに自分の矢印の矢じりの根元 `headAt` を持ち、分けた矢印でもそれぞれの矢じりに尾が付く)。はじめは根元から数えていて、矢じりの手前が隙間になり、矢じりだけが離れて浮いて見えた。破線の四角は、左右の縁、切れ目、根元の端をすべて塗りのシェーダーの中で四角の内側に描き(画面上で約 3.5 画素)、輪郭で囲む(尾の付け根には引かない)。はじめは左右の縁を線の帯(縁を中心にした帯)で描き、切れ目の線だけを塗りの中に描いていて、帯の外側半分が角で途切れた。実線の矢印の縁取り(線の帯)は、塗りのすぐ上(約 200m、`ARROW_OUTLINE_RADIUS`)に描く。線と同じ高さ(約 1km 上)だと、傾けて見たときに縁取りが画面の上へずれた。はじめは縁取りだけを破線にして塗りを半分の濃さにしていたが、薄い矢印に見えて破線と分からなかった。区切りを帯の太さの 4.5 倍にしたときは、塊が並んでいるように見えた。`offset`(km)で根元と先端の近くだけを横へずらせる(正は進む向きの右。端から帯の太さの 4 倍、全体の 35% までの範囲で、なめらかに 0 へ戻す。途中は渡した点を通る)。同じ所から出る・同じ所へ向かう矢印の重なりを避ける。急に曲がる所で帯が重なっても二重に塗らない(範囲の塗りと同じく奥行きを書き込む)。塗りは範囲の塗りより上、線より下の高さ。矢じりの根元は、先端からまっすぐ測って矢じりの長さだけ離れた曲線上の点にし、矢じりの軸を根元から先端への向きにする(はじめは根元での曲線の向きを軸にしていて、矢じりの区間で道筋が曲がると矢じりが片側へ偏った。左右対称を確かめるテストあり)。ハンニバルのアルプス越え(約 1,150km)とローマ軍の推定の動き(破線、40km)で、実アプリの地域ビューで確かめた。保存したツアー「ハンニバルのアルプス越え」は、行軍の線(場面 1、2、7、8)を太い矢印にした(場面 2 は 10km、場面 7 は 12km、ほかは長さから決める)。峠の 3 つの説(場面 3〜6)も、ユーザーの判断で太い矢印にした。本命のトラヴェルセット峠は実線、クラピエ峠と小サン・ベルナール峠は破線。場面 3 は 3 本とも 10km で、ヴィエンヌから出てトリノに着くので、クラピエ峠を右へ 12km、小サン・ベルナール峠を左へ 12km ずらした。場面 4〜6 は 5km。どれも前の場面から続くので根元を消す。場面 4〜6 はカメラを寄せきれず(地域ビューの一番近い距離のため)、矢印が小さく見える。保存したツアー「シルクロード」は、場面 2〜9 の道を太い矢印にした(字幕が東から西へたどる向き)。場面 1 の全体の地図も、ユーザーの判断で太い矢印にした(陸の道と海の道、どちらも 100km)。2 本が同じ所から出る場面 4(北の道と南の道)と、範囲より太く見えた場面 2(河西回廊)は 30km、長い海の道(場面 - **見た目の指定:** どの種類にも `label`(画面に出す名前)、`color`(CSS の色。線と縁取りは光らせ、ラベルの文字と点の印も同じ色にする)、`dashed`(破線。推定のルートや別の説)、`arrows`(進む向きの矢印。座標で渡す線は既定で付け、川は既定で付けない)、`countries`(通る国・重なる国の名前を出すか。歴史の話では false。結果の一覧には入る)を付けられる。矢印は線の途中に 6 個と終点に 1 個で、光る線がそこまで伸びてから出る。破線は線全体を 36 の区切りに分ける。

- **流れる光(2026-11-07):** なぞり終えた川と座標の線に、源流から河口へ流れる明るい波を通す(`highlights.ts` の `FLOW_*`)。線全体に 8 つの波を並べ、1 つの場所を 2.5 秒で 1 つ通り過ぎる。色相は変えず明るさだけを、波のない所で 0.8 倍、波の山で約 1.25 倍にする(川は明るく、上げても見た目が変わりにくいので、谷を下げて波を見せる)。矢印も同じ波で明るくする。範囲の縁取りには、流れる波ではなく、縁に沿って場所ごとにばらばらな明るさの揺れ(きらめき)をゆっくり動かす(`TWINKLE_*`。1 周 24 区画をなめらかにつないだ値の揺れで、明るさは 0.65〜1.45 倍)。はじめは 48 区画・0.85〜1.3 倍にしたが、縁は細く雪などの明るい地面に埋もれて分からなかったので強めた。縁の始点と終点がつながる 1 か所は区画が切り替わる。なぞっている間は先端を明るくするだけで、なぞり終えてから波を入れる。川は流れる光で向きが分かるので、`arrows` を指定されても矢印は描かない(座標の線は今までどおり)。試したが採らなかったもの: 線のまわりに太い帯でグラデーションを描く方法は、線分ごとの四角形の角が曲がり角で飛び出してギザギザになり、重なりも濃くなったのでやめた。
- **カメラを寄せる:** 示しているハイライトが画面に収まるよう、地域ビューのカメラを寄せる・引く(`region-camera.ts` の `frameRegionView`、検証用フックの `frameHighlights({ heading, tilt, seconds })`)。収める点は、川と線は沿った点、範囲は重心と縁、点はその位置で、通る国の国名は国の中央にあって対象から遠いことがあるので含めない。中心は点の球面上の平均にし、方角と傾きは指定のもの(省くと今のまま)。全部の点が地球の手前にあり、画面の余白の内側に入る一番近い距離を二分探索で求める(地域ビューの距離の範囲 0.07〜1 の中。収まらなければ 1。一番近い距離は 2026-11-06 に 0.1 から下げた。0.04 まで下げると地表の画像の粗さが目立った)。余白は画面の半分に対して上 16%、左右 16%、下 38%(字幕と操作のボタンの分)。遠くへは視点の呼び出しと同じく途中で高く上がって飛ぶ。求めたとおりの姿勢に着くよう、寄せる前に自動の旋回や巡航を止める(止めないと、自動旋回がオンのとき着いた画面が回ってずれた)。MCP の `show_area` はこれを使う。
- **歴史のルートの例(2026-11-06 にデモ):** ハンニバルのアルプス越え(前 218 年)。座標と台本は Claude が組み立て、CDP から検証用フックを呼んで描いた。場面 1 は西地中海の全体で、カルタゴ・ノウァからピレネー、ローヌ川を経てトリノまでの行軍(橙の実線と矢印)。場面 2 はアルプスで、トラヴェルセット峠の説(橙の実線)と、クラピエ峠、小サン・ベルナール峠の説(淡い色の破線)を並べ、峠に標高付きの印を立てた。場面 3 はイタリアで、ハンニバル軍(橙)とローマ軍のスキピオ(赤)の動きと、ティキヌス、トレビア、トラシメヌス湖畔、カンナエの戦い(赤い印)。どの場面もラベルの重なりは 0 件。近い点(ティキヌスとトレビア、約 45km)は、ラベルが重なるので、ずらす処理を入れる前は片方が出なかった。今はティキヌスの名前が印の左へずれて両方出る。カメラの位置は、はじめは場面ごとに手で決めていたが、`frameHighlights` で自動で寄せるようにした(余白が上下で同じだった間は、場面 1 の出発地が字幕に隠れた)。ルートは諸説のうちの一つの推定で、線の細かさは数十 km 程度。
- **山の例(2026-11-06 にデモ):** 「アルプス山脈の主要な山を教えて」。場面 1 はアルプス山脈の範囲と 10 の山(データにあるモンブラン、モンテ・ローザ、マッターホルン、フィンシュターアールホルン、グロースグロックナー、ツークシュピッツェ、トリグラウと、座標と標高で置いたグラン・パラディーゾ、ユングフラウ、アイガー、ピッツ・ベルニナ)。場面 2 は西側の 4,000m 級の 4 山、場面 3 はスイス中央部と東側の山。全体の場面ではラベルが混み、11 山のうち 1 つ(フィンシュターアールホルン)の名前は空きがなく出なかった。
- **範囲の塗り(2026-11-06):** 一様な半透明の塗りをやめ、輪郭が一番濃く内側へ行くほど薄くなるグラデーションにした(輪郭から内側へ広がる光)。塗りの頂点ごとに輪郭までの距離(km)を求めて持ち、シェーダーで `exp(-距離 / 幅)` で薄くする。幅は範囲の中央から輪郭までの距離の 22%(12〜90km)。品よく見えるよう、輪郭のすぐ内側でも不透明度 0.22、中央は その 4% と薄くする。グラデーションがなめらかになるよう、三角形は 0.25 度以下に分ける(アルプスで約 2 万 3 千、計算は約 0.1 秒。サハラは約 2 秒かかる)。補間でわずかに負の距離になる画素で exp が大きくなり、明るい四角が出たので、距離を 0 以上、明るさを 1 以下に抑える。三角形が重なっても半透明が足し合わさらないよう、塗りは奥行きを書き込み、同じ深さの 2 枚目以降は描かない。砂漠のように色の近い地面では、縁の光が見えにくい。
- **ツアーの再生(`tour.ts`):** 場面の並び(`{ highlights, caption, camera: { heading, tilt, orbit } }`)を受け取り、字幕をクリックするたびに次の場面へ進む。文字を出している途中のクリックは、残りを出し切るだけにする。最後の場面でクリックすると最初に戻り、何度でも繰り返せる。Esc で終え、ハイライトと字幕を消す。字幕の下に「2 / 5 クリックで次へ · Esc で終わる」を出す。`orbit` は着いてから中心のまわりを回る速さ(旋回の段 -5〜5)で、省くと回らない。全体を見せる場面は回さず、山や峠に寄った場面で回すと見やすい。検証用フックの `playTour(scenes)`、`stopTour()`。MCP の `play_tour` はこれを使う(字幕のクリックの代わりに、秒数で進める指定も足す予定)。
- **時刻:** ツアーの場面ごとに見せる時刻を指定できる(`time: { hour }` はその場所の地方時、`{ iso }` は日時そのもの。`tour-time.ts`)。地方時は、カメラを寄せた先の中心の経度から求める(経度 15 度で 1 時間)。変えるときは 2.5 秒かけて太陽を動かし、日をまたいで 1 周しないよう差を ±12 時間に収める。ツアーの途中でも、人が時刻のスライダーを動かしたらそちらを優先する。ツアーを終えると元の時刻(今、またはスライダーの時刻)に戻す。字幕のクリックは 0.6 秒以内に続けて届いたものを無視する(ダブルクリックで場面を飛ばさない)。

- **字幕:** 画面の下の中央(右下の操作のボタンと重ならないよう、下の段より上)に、半透明の板で説明の文を出す(`tour-caption.ts`)。文字は先頭から 1 秒に約 28 文字の速さで順に現れる(ストリーミング表示)。板の大きさが変わらないよう、最初から全文を置いてまだ出していない部分を透明にする。ふわっと現れて消え、秒数を渡すと全文を出し終えてからその秒数で消える。`finish()` で残りをすぐに出せる。今は検証用フック(`caption(text, seconds)`、`clearCaption()`)から呼ぶ。
- **国名と国旗:** 川が通る国(源流に近い順)と、範囲に重なる国(重なりの大きい順)を、変換のときに Natural Earth の国のデータ(`ne_10m_admin_0_countries`)から求めて持つ。川は約 5km ごとに国を調べ、通った長さが 1km に満たない国は国境との誤差として除く(ドナウ川のモルドバは接する区間が短く除かれる)。範囲は内部に格子状に点を打ち、3% 以上重なる国を残す。国名は国の中央付近の点(`LABEL_X`、`LABEL_Y`)に国旗を添えて出し、川は光る線がその国に差しかかってから出す。日本語名は Natural Earth の `NAME_JA` を使い、台湾、中国、韓国、北朝鮮、アメリカ、タイ、マリなど、正式名に近いものは日本の地図で一般的な短い名前に直す(`JA_OVERRIDES`)。国旗は npm の flag-icons(MIT)の SVG を `src/renderer/public/flags/` に写して使う(239 枚、2.0MB)。Windows では国旗の絵文字が国旗にならないため。`highlight` の結果に国の一覧を含めるので、小さめの LLM でもデータに基づいて説明できる。変換は国の判定に約 6 分かかる。
- **雲:** ハイライトは雲の下に描く(地表の上のものなので)。見えにくいときは、ツアーの台本で場所ごとに `"mode": "normal"`(雲を出さない)にするか、`set_mode` で切り替える。ハイライトのまわりだけ雲を薄くする工夫も候補(未検討)。
- **ラベルの重なり:** ハイライトのラベルを先に置く。点のハイライトの印は名前と別の要素で、いつも点の位置に置き、ほかのラベルを重ねない。国名、点の名前、範囲の名前は、重なるときは出さずにずらす(点の名前は印の右、左、斜め、上下、国名と範囲の名前は中央、上下、左右の順に空いている所を探す。ちらつかないよう、前のフレームのずらし方が空いていればそれを使う)。国名は位置が決まっているので先に、川や範囲の名前は候補の点のうち空いている所を選ぶ。都市のラベルと設定の国名は、そのあとでハイライトのラベルを避けて置く(重なるものは出さない)。
- **気になっている点:**川の色は HDR で明るくしているので、白っぽく見える。川の長さは Natural Earth の線の長さで、実際の全長(ドナウ川は約 2,850km)より短い。日本の川は少ない(利根川、石狩川はあるが、信濃川はない)。

2026-11-06 に Web で調べた内容。実際に動かして確かめる必要がある。

- **形:** 26B A4B(総パラメータ 26B、動くのは約 4B の MoE)。知識の量は 26B 相当で、速さは 4B に近い。
- **コンテキスト:** 約 256K トークン。台本とツールの説明には十分。
- **画像:** 読める。ただし画像用の部分を読み込むと VRAM を使い、置けるコンテキストが減る。
- **VRAM:** 4bit の量子化で、コンテキスト 8K〜32K なら約 18GB という目安がある。16GB の GPU で 4bit・96K を動かしたが「かなりきつい」という報告もある。この PC の GPU で確かめる。
- **ツール呼び出し:** モデルの説明では対応しているが、使う側のテンプレートが OpenAI の関数呼び出しと完全には合わず失敗した、llama.cpp で動かなかった、という報告がある。使う実行環境(LM Studio、llama.cpp)で、まず 1 つのツールを確実に呼べるか試す。
- **ツール呼び出しが不安定なときの逃げ道:** 構造化出力(JSON Schema に沿った出力)で台本だけを書かせ、それをアプリへ渡す小さなスクリプトを用意する。`play_tour` は台本 1 つで完結するので、ツール呼び出しなしでもツアーはできる。
- **VRAM の使い方:** MCP クライアントのアプリが必要なときだけモデルを読み込み、使い終わったら解放する設定にする。アプリの描画(地域ビューの画像で約 450MB)と同時に動くので、GPU の空きに注意する。

## 進め方

1. **MCP サーバーの土台:** メインプロセスに HTTP の MCP サーバーを置き、`get_view` と `fly_to` だけ作る。Claude Code から呼べることを確かめる。
2. **見る・映す:** `show_area`、`screenshot`、`set_mode`、`set_view`、`set_time` を足す。
3. **ツアー:** `play_tour` と `stop_tour`、字幕の表示を足す。Claude Code で「世界の長い川」を試す。
4. **ローカル LLM:** LM Studio などで Gemma 4 26B をつなぎ、ツール呼び出しが動くか、同じツアーがどの程度できるかを Claude と比べる。動かなければ、構造化出力で台本だけ書かせる方法を試す。
5. **設定と記録:** MCP サーバーのオンオフとポートを設定に足し、plan.md と progress.md に結果を書く。

## 決めていないこと

- ポートの番号と、設定画面のどこに置くか
- 字幕の見た目(位置、大きさ、出し方)と、ツアー中にパネルを隠すか
- ツアーの途中で人が操作したとき、止めるだけか、元の視点まで戻すか
- `screenshot` の画像の大きさ(縮小して送るか)
- 簡単な合言葉(トークン)を付けるか。`127.0.0.1` だけで待ち受けるが、同じ PC の他のアプリからは呼べてしまう
